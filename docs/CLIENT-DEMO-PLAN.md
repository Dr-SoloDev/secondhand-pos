### 3. รับซื้อของ — Purchase Order Workflow (10 นาที) ⭐

**หน้า:** `admin/purchase-orders.html`

**Flow ที่จะโชว์:**

```
1. ค้นหาผู้ขาย (top-left, เป็นอันดับแรก) ← ⭐ WF-05 เปลี่ยน
2. เลือกราคาชั้น (บิล1/2/3) — บิล1 auto ✅
3. เลือกสาขา
4. ค้นหาสินค้า → ถ้าผลลัพธ์เดียว auto-select → ไปน้ำหนัก
5. ใส่น้ำหนัก (focus → select-all → พิมพ์ทับ)
6. เพิ่มสินค้าใน cart
7. บันทึกใบรับซื้อ
8. พิมพ์ใบรับซื้อ (2 แบบ: ปกติ + โลหะมีค่า)
```

**Talking Points:**
- ⭐ **Keyboard-first** — Tab ล้วนๆ ไม่ต้องใช้เมาส์
- ⭐ **Auto-select tier** — บิล1 เริ่มต้น ไม่ต้องกด
- ⭐ **Auto-select สินค้า** — ถ้าพบ 1 รายการ → เลือกให้อัตโนมัติ
- รับซื้อทีละหลายรายการในบิลเดียว
- Auto-fill ราคาตามสินค้า — พนักงานไม่ต้องจำราคา
- ⭐ มีน้ำหนักหักกระสอบ
- รองรับ 3 ระดับราคา

### 4. ระบบผู้ขาย + ID Card (10 นาที) 🔴 **CRITICAL**

**หน้า:** `admin/sellers.html` + ระหว่างสร้าง PO

**สิ่งที่โชว์:**

**4.1 — การลงทะเบียนผู้ขายใหม่**
- ค้นหาผู้ขายด้วย: เบอร์โทร / ชื่อ / เลขบัตร ปชช.
- สร้างผู้ขายใหม่:
  - ✅ ชื่อ-นามสกุล
  - ✅ เลขบัตรประชาชน 13 หลัก (validate)
  - ✅ ที่อยู่
  - ✅ เบอร์โทร
  - ✅ ทะเบียนรถ (ถ้ามี)
  - ✅ 📸 รูปบัตรประชาชน

**4.2 — ระบบป้องกัน ID Card ซ้ำ**
- ถ้าเลขบัตรซ้ำ → แจ้งเตทันที
- บังคับกรอกเลขบัตร ถ้าสินค้าเป็นโลหะมีค่า

**4.3 — Blacklist**
- ผู้ขายที่ถูก blacklist → alert popup สีแดง ตอนค้นหาผู้ขาย
- แสดงเหตุผล + วันที่ + คนที่ blacklist

**4.4 — PDPA Consent**
- ✅ มี checkbox consent ก่อนบันทึกข้อมูล
- ✅ เก็บ timestamp `pdpa_consented_at`

**4.5 — ประวัติผู้ขาย**
- Modal แสดงประวัติการขายทั้งหมดของผู้ขายคนนั้น
- สรุปยอดรวม จำนวนครั้ง

**Talking Points (สำคัญ):**

> "ที่ลูกค้าซีเรียสคือเรื่องนี้ — เราเข้าใจดี
> ระบบนี้เก็บบัตรประชาชนผู้ขาย พร้อมรูปถ่ายบัตร
> กันไม่ให้รับของโจร ตาม **มาตรา 357**
> และบันทึกข้อมูลครบถ้วนตาม **พรบ.ควบคุมการค้าของเก่า 2474**
> มี Blacklist ป้องกันขาประจำที่ขายของต้องสงสัย
> มี PDPA Consent กันความผิดเรื่องข้อมูลส่วนบุคคล"

  - ✅ มีลายเซ็นผู้ขาย (เซ็นบนหน้าจอ)

**Talking Points:**
- สินค้าเสี่ยงสูงต้องมีลายเซ็น — ป้องกันปัญหาทีหลัง
- ใบรับซื้อ 2 แบบ: ปกติ vs โลหะมีค่า

### 6. ขาย Lot — เอาของออก (5 นาที)

**หน้า:** `admin/sale-lots.html`

- Draft → Confirm → Cancel
- ระบบคิด FIFO cost อัตโนมัติ
- Track กำไรต่อ Lot

**Talking Points:**
- ขายเป็น Lot ให้โรงงาน (ไม่ใช่ขายปลีก)
- ระบบรู้ต้นทุนถัวเฉลี่ย + FIFO
- รู้ว่าล็อตนี้กำไร/ขาดทุนเท่าไหร่

## เทคนิคการนำเสนอ

### เปิดตัวแรง — เปิดด้วย Compliance

> "เรารู้ว่าลูกค้ากังวลเรื่อง **มาตรา 357 และ พรบ.การค้าของเก่า** มากที่สุด
> เราเลยออกแบบระบบนี้ให้ **การเก็บข้อมูลผู้ขายเป็นหัวใจของระบบ**
> ตั้งแต่: เลขบัตรประชาชน, รูปถ่ายบัตร, ลายเซ็น, Blacklist, PDPA consent
> รับซื้อของมีค่าทุกครั้ง ระบบจะบังคับให้กรอกข้อมูลผู้ขายให้ครบ"

### ย้ำตลอดว่า = ปัญหาที่เขาจ้างเรามาแก้

> "ที่ผ่านมาทางร้านจดใส่สมุด — เสี่ยงทำตก หาย ตรวจสอบลำบาก
> ระบบนี้ **เก็บข้อมูลเป็นระบบ** — ค้นหาได้ พิมพ์ได้ ส่งให้ตำรวจหรือสรรพากรได้
> และป้องกันความผิดตามกฎหมาย"

### ปิดด้วย Trust

- บอกว่าซอร์ฟแวร์นี้ถูกใช้จริงแล้ว
- มีระบบ backup
- มี maintenance รายเดือน
- อยู่สุรินทร์ — มาเคลียร์หน้างานได้
