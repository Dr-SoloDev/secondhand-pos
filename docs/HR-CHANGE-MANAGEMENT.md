## 1. PEOPLE IMPACT ASSESSMENT

### ผู้ได้รับผลกระทบ

| กลุ่มคน | ผลกระทบบวก | ผลกระทบลบ | ระดับความกังวล |
|---|---|---|---|
| แคชเชียร์ | งานเป็นระบบ, มี backup | เรียนรู้ระบบใหม่, กลัวผิดพลาด | สูง |
| ผู้จัดการสาขา | รายงานอัตโนมัติ | เพิ่มงาน onboarding | กลาง |
| ผู้ขาย (sellers) | ได้ใบเสร็จจริง, ราคาโปร่งใส | รู้สึกถูกตรวจสอบ (ถ่ายรูป ID) | **สูงมาก** |
| เจ้าของร้าน | compliance ครบ, ไม่ติดคุก | ลงทุนเริ่มต้น, อบรมพนักงาน | กลาง |

### ความกังวลที่ต้องจัดการก่อนวันแรก

**สำหรับผู้ขาย (Critical):**
เมื่อพวกเขาเห็นระบบดิจิทัล จะคิดทันทีว่า:
- "ข้อมูลผมจะไปอยู่ที่ไหน?"
- "ทำไมต้องถ่ายรูปบัตร?"
- "ราคาจะยังยุติธรรมไหม?"

**สำหรับแคชเชียร์ (High):**
- "ถ้าทำระบบพัง จะโดนตำหนิไหม?"
- "ถ้าทำช้ากว่าเดิม จะถูกมองว่าไม่เก่ง?"

## 2. CHANGE MANAGEMENT PLAN — 6 สัปดาห์

### หลักการ: "Launch เป็น Human Event ไม่ใช่ IT Event"

ความล้มเหลวของระบบส่วนใหญ่ไม่ได้มาจาก bug — มาจากคนที่ไม่เชื่อในระบบ

### Timeline

**สัปดาห์ 1-2: LISTEN (ฟัง)**
- สัมภาษณ์ผจก.สาขาทั้ง 4 — workflow จริงเป็นอย่างไร
- นั่งดูแคชเชียร์ทำงาน 1 วัน (shadow day)
- คุยกับผู้ขาย 5-10 ราย — เขากลัวอะไร ต้องการอะไร

**สัปดาห์ 3: BUILD CHAMPIONS**
- เลือก "ผู้นำการเปลี่ยนแปลง" 1 คน/สาขา
- อบรม champion ก่อน — ให้เขาเป็น "คนที่เพื่อนถามได้"
- ให้ champion มีส่วนร่วม test ระบบ — ความเป็นเจ้าของเริ่มจากนี้

**สัปดาห์ 4: TRAIN**
- อบรมเป็น role-based ไม่ใช่ feature-based
- ภาษาไทยล้วน — ไม่มี jargon อังกฤษ
- ฝึกซ้อมกับข้อมูลจำลอง — ไม่มีโทษถ้าผิดพลาด

**สัปดาห์ 5: PILOT (1 สาขา)**
- Run parallel: ระบบเก่า + ระบบใหม่ 2 สัปดาห์
- เก็บ feedback ทุกวัน

**สัปดาห์ 6: ROLLOUT (3 สาขาที่เหลือ)**
- Stagger launch ไม่พร้อมกัน
- Champion สาขา pilot มาช่วย support สาขาใหม่

### Communication Plan

กับผู้ขาย:
> "ระบบนี้ช่วยให้คุณได้เงินตรงตามที่ตกลง มีหลักฐาน มีใบเสร็จ ข้อมูลของคุณใช้แค่ตามกฎหมาย ไม่แชร์ที่ไหน"

กับแคชเชียร์:
> "ระบบนี้ช่วยให้งานคุณง่ายขึ้น ถ้าทำผิดพลาดบนระบบแก้ได้ตลอด — มีปุ่มแก้ไข ไม่มีใครโดนตำหนิเพราะเรียนรู้"

กับผจก.สาขา:
> "คุณจะเห็นตัวเลขจริง ไม่ต้องรอสรุปสิ้นเดือน ตัดสินใจได้เร็วขึ้น"

## 3. G4 EMPLOYEE MODULE — Requirements

### Must Have

| # | Feature | รายละเอียด |
|---|---|---|
| M1 | Employee Profile | ชื่อ, รูป, เลขบัตร, เบอร์, สาขา, ตำแหน่ง, วันเริ่มงาน, สถานะ |
| M2 | Role & Permission | กำหนดสิทธิ์: แคชเชียร์ทำ PO ได้แต่ลบ record ไม่ได้ |
| M3 | Basic Shift | กะเช้า/บ่าย/flexible — ใครอยู่วันนี้ |
| M4 | Activity Log ต่อพนักงาน | transaction ไหนทำโดยใครเวลาไหน (audit trail ม.357) |

### Should Have

| # | Feature | รายละเอียด |
|---|---|---|
| S1 | Simple Payroll Summary | จำนวนวัน x อัตรา = ยอดจ่าย, export PDF |
| S2 | Attendance Check-in/out | กดปุ่ม "เริ่มงาน/หยุดงาน" หรือ PIN 4 หลัก |
| S3 | Branch Transfer History | พนักงานคนนี้เคยทำสาขาไหนมาบ้าง |

### G4 Integration Dependencies

```
G4 (Employee) ─── Auth: login = employee account
               ─── PO: PO สร้างโดย employee id ใด
               ─── Compliance: audit log ต้องมี employee id
               ─── Reports: ผลงานรายคน, สาขา
```

## 4. DIGNITY-IN-DESIGN RECOMMENDATIONS

### Layer 1: Seller Experience

| # | Recommendation | Implementation |
|---|---|---|
| DIG-01 | ต้อนรับด้วยชื่อ | "สวัสดีคุณ[ชื่อ]" แทนตารางข้อมูล |
| DIG-02 | ใบเสร็จที่อ่านได้ | "น้ำหนัก x ราคา/กก. = ยอดรับ" — ไม่ใช่แค่ตัวเลข |
| DIG-03 | Photo Consent screen | "เราต้องเก็บรูปบัตรตาม ม.357 — ข้อมูลจะไม่แชร์" ก่อนยิงกล้อง |
| DIG-04 | Seller History ที่ให้คุณค่า | "ร่วมงานกันมา 2 ปี 3 เดือน | รวมซื้อ 47 ครั้ง" |

### Layer 2: Cashier Experience

| # | Recommendation | Implementation |
|---|---|---|
| DIG-05 | Error Messages ไม่ทำให้รู้สึกโง่ | "ยังไม่ได้เลือกผู้ขาย — กดค้นหาชื่อได้เลย" |
| DIG-06 | Undo ได้เสมอ | confirm + undo window 30 วินาที หลัง save |
| DIG-07 | End-of-Day Summary | "วันนี้รับซื้อจาก 23 คน มูลค่า 15,400 บาท ดีมาก" |

### Layer 3: Empty States & Mission

| # | Recommendation | Implementation |
|---|---|---|
| DIG-08 | Empty State ที่มีความหมาย | "ยินดีต้อนรับ — วันแรกของสาขาใหม่ พร้อมเริ่มต้นด้วยกันไหม?" |
| DIG-09 | Mission Statement ใน UI | ใน About/Settings: "scrap-pos สร้างมาเพื่อให้คนเก็บของเก่าได้รับความเป็นธรรม" |

### Layer 4: Language & Tone

**เปลี่ยน → เป็น:**
- "Seller" → "ผู้ขาย" หรือ "คุณลูกค้า"
- "Transaction" → "การรับซื้อ"
- "Record not found" → "ยังไม่มีข้อมูล — เพิ่มได้เลย"
- "Error 403" → "ขออภัย — คุณไม่มีสิทธิ์ส่วนนี้"

**อย่าใช้:** "Track", "Monitor", "Suspect", "Flag" ในหน้าที่เกี่ยวกับผู้ขาย
