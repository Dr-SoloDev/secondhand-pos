# PRD & Implementation Plan: Unified Owner's Dashboard (ศูนย์ควบคุมหน้าเดียวสำหรับเจ้าของกิจการ)

เอกสารฉบับนี้ร่างขึ้นเพื่อใช้เป็นข้อกำหนดความต้องการทางซอฟต์แวร์ (Product Requirement Document - PRD) และแผนงานการพัฒนา (Phased Roadmap) สำหรับการปรับปรุงหน้าจอสรุปธุรกิจเพื่อตอบโจทย์ผู้ประกอบการร้านรับซื้อของเก่า

---

## 1. ข้อมูลทั่วไป (Overview)
*   **เป้าหมายโครงการ:** เปลี่ยนหน้าจอสรุปการเงินปัจจุบันให้เป็น "ศูนย์ควบคุมกิจการในหน้าเดียว (Unified Dashboard)" ที่ช่วยลดการคลิกสลับหน้าจอ และออกแบบให้ใช้งานง่ายที่สุดสำหรับเจ้าของร้านรุ่นเก่าที่ไม่ได้คุ้นชินกับระบบไอทีซับซ้อน
*   **กลุ่มผู้ใช้งานเป้าหมาย (Persona):** เจ้าของร้านของเก่า (Owner / Admin) ที่บริหารแบบครอบครัว เน้นความโปร่งใส ปลอดภัยของเงินสด และต้องการตัดสินใจระบายสต็อกแบบเห็นผลเร็ว (Action-oriented)

---

## 2. หลักการออกแบบประสบการณ์ผู้ใช้ (UX Design Principles)
1.  **ซ่อนความซับซ้อน (Progressive Disclosure):** แสดงผลเฉพาะสถานะแจ้งเตือนหลักและสิ่งที่ต้องอนุมัติทันทีในหน้าแรก หากผู้ใช้ต้องการดูตัวเลขเชิงลึกหรือข้อมูลทางบัญชีค่อยกดคลิกขยายดู
2.  **ใช้สีสื่อความรู้สึก (Traffic Light System):** ใช้สี เขียว (ปกติ) / เหลือง (แจ้งเตือน) / แดง (วิกฤต/ต้องดำเนินการทันที) แทนการเพ่งดูตัวเลขละเอียด
3.  **ภาษาชาวบ้าน (Traditional Friendly Language):** หลีกเลี่ยงศัพท์การเงินที่ซับซ้อน เช่น เปลี่ยน `Variance` ➔ `ยอดเงินไม่ตรงในลิ้นชัก`, เปลี่ยน `Inventory Threshold` ➔ `โกดังเก็บของใกล้เต็ม`

---

## 3. มิติฟีเจอร์การควบคุม 3 ด้าน (Core Features)

### 📊 มิติที่ 1: ตรวจสอบสถานะการดำเนินงานปัจจุบัน (Present: Operational Audit)
*   **กล่องเงินสดในมือทุกสาขา (Cash Drawer Status):**
    *   แสดงสถานะว่าลิ้นชักแต่ละสาขาเปิดหรือปิดกะอยู่ และมียอดเงินสดในมือเท่าใด
    *   แจ้งเตือน (สีเหลือง/แดง) ทันทีหากมียอดเงินสดคาดการณ์สะสมในร้านสูงเกินขีดจำกัด (เช่น เกิน 100,000 บาท) เพื่อให้เจ้าของสั่งการลูกน้องนำเงินฝากธนาคาร
*   **ศูนย์รวมการอนุมัติหนึ่งเดียว (Unified Approvals Queue):**
    *   รวบรวมรายการรอแอดมินอนุมัติทั้งหมด (เช่น การขอปิดกะที่มีส่วนต่างเกิน 100 บาท, การขอยกเลิกใบรับซื้อ, ใบเบิกรายจ่ายร้านราคาสูง) ให้เจ้าของกดอนุมัติผ่านหน้าแรกได้ทันที

### 📈 มิติที่ 2: การวิเคราะห์และทำนายอนาคต (Future: Business Analytics)
*   **ความจุสต็อกและคำเตือนล้นคลัง (Warehouse Capacity Alerts):**
    *   ระบบประเมินน้ำหนักสต็อกปัจจุบันเทียบกับความจุสูงสุดของโกดัง (เช่น สต็อกเหล็กสะสมได้ 10 ตัน ตอนนี้มี 9.2 ตัน) ระบบจะขึ้นเตือนให้เตรียมจ้างรถขนส่งไปขายโรงงานใหญ่
*   **เครื่องมือประมาณการกำไร Lot ถัดไป (Margin & Profit Estimator):**
    *   ดึงราคาทุนเฉลี่ยของสินค้าในสต็อกปัจจุบันเทียบกับราคารับซื้อของศูนย์ in วันนั้น เพื่อแสดงยอดกำไรคาดการณ์เชิงรุก ช่วยเจ้าของประเมินว่าควรขายวันนี้หรือจะรอสะสมเพิ่ม

### 📅 มิติที่ 3: ระบบกรองเวลาที่ยืดหยุ่น (Past: Flexible Time Filters)
*   เพิ่มการกรองข้อมูลแบบ **"รายวัน (Daily)"** เพื่อเช็คผลงานวันนี้ และแบบ **"เลือกช่วงวันที่เอง (Custom Date Range)"** เช่น 7 วันย้อนหลัง เพื่อวิเคราะห์แนวโน้มยอดขาย

## 4. แผนงานการพัฒนา (Phased Roadmap)

### 📌 ระยะที่ 1: ปรับปรุงโครงสร้างระบบกรองเวลาหลังบ้าน (Backend API Filters)
*   **รายละเอียด:** ปรับปรุงฟังก์ชัน `getPeriodParams()` ใน `FinancialController.php` ให้รองรับพารามิเตอร์ `period=day` และ `date_from`/`date_to` จาก Client
*   **ผลลัพธ์:** หลังบ้านพร้อมกรองงบสรุปแบบรายวันและรายสัปดาห์ได้

### 📌 ระยะที่ 2: พัฒนา API รวบรวมข้อมูลหลังบ้าน (Owner Dashboard API Endpoint)
*   **รายละเอียด:** สร้าง API ชุดใหม่เพื่อรวมผลลัพธ์ของ:
    *   ยอดรวมเงินในลิ้นชักจากทุกสาขา (`cash_sessions` table)
    *   รายการรอคำอนุมัติทั้งหมด (ยอดส่วนต่างผิดปกติ, คำขอยกเลิก PO, คำขอเบิกจ่าย)
*   **ผลลัพธ์:** หน้าจอหน้าบ้านสามารถยิง API เส้นเดียวแล้วดึงสถานะทั้งระบบมาแสดงผลได้

### 📌 ระยะที่ 3: ออกแบบหน้าจอ UI (Traditional Friendly UI Implementation)
*   **รายละเอียด:** แก้ไขไฟล์ `financial-summary.html` และ JS
    *   เพิ่มสวิตช์ปิด/เปิดตัวกรองเวลา (รายวัน/รายเดือน)
    *   จัดทำแถบ Widget "สิ่งที่รอการแก้ไขอนุมัติวันนี้" และ "เตือนภัยสต็อก" ไว้ด้านบนสุด
*   **ผลลัพธ์:** หน้ารวมศูนย์เสร็จสมบูรณ์พร้อมให้ทดสอบการใช้งานจริง
