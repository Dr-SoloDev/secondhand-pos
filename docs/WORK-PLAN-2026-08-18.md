### 🐛 Bug ที่ผมเจอ + แก้ (ในโค้ด Codex — สำคัญ!)
- **อาการ:** ตั้ง baseline โดยลิ้นชักมีเงินอยู่แล้ว (drawer=12,000) → เปิดรอบวันด้วย 12,000 → drawer กลายเป็น **24,000** (เงินนับซ้ำ)
- **สาเหตุ:** `openPositionDay` คำนวณ `transfer = min(actual, reserve)` เสมอ — ไม่หักเงินที่อยู่ในลิ้นชักแล้ว → design (4.1) บอกว่า transfer = เฉพาะส่วนที่ขาด
- **แก้:** `needToBring = max(0, actual - drawer_balance)` → transfer = min(needToBring, reserve) → capital = needToBring - transfer
- **กันกลับ:** เพิ่ม regression test 4 ตัวใน `test_cash_position.sh` (branch 1: baseline drawer=12,000/reserve=50,000) — **20/20 ผ่าน**
- test เดิม (drawer=0) ไม่จับ bug นี้ — นั่นคือช่องโหว่ของชุดทดสอบเดิม
